# DaVinci Director

Монтаж відео через текст для DaVinci Resolve. Текст і таймлайн Resolve — це два способи редагувати один і той самий монтаж:

- видаляєте слова в тексті — з таймлайна вирізається відповідний шматок відео (ripple);
- переставляєте фрагмент тексту — переставляються кліпи;
- повертаєте вирізаний текст — відео повертається на місце;
- копіюєте чи дублюєте фрагмент — відео дублюється;
- видаляєте, переставляєте, обрізаєте або додаєте кліпи в Resolve — текст оновлюється сам.

Плюс транскрибування з мовцями (Parakeet TDT 0.6B v3 UK + pyannote), експорт транскрипції для Claude, імпорт запропонованих сюжетів і застосування їх до реального таймлайна.

Власного в'ювера чи таймлайна немає. Усі операції виконуються над кліпами активного таймлайна Resolve.

## Встановлення (Windows)

Друзям — інсталятор `DaVinci Director-Setup-<версія>.exe` (див. «Збірка інсталятора»). Потрібна **DaVinci Resolve 21.1.2+** (Free або Studio). Усе інше (аудіо, нейромережі, модель розпізнавання) програма завантажить сама під час першої транскрипції. З відеокартою NVIDIA розпізнавання й визначення мовців працюють на ній, без неї — на процесорі.

З вихідного коду (для розробки):

```powershell
python install.py              # .venv + прихований запуск разом з Windows
python install.py --uninstall  # зупинити й прибрати автозапуск
```

## Запуск

1. У DaVinci Resolve відкрийте проєкт і таймлайн із записом.
2. У меню Resolve: **Workspace > Scripts > DaVinci Director**. Відкриється панель DaVinci Director. Пункт є на будь-якій сторінці.

Окремих ярликів немає. Resolve 21 Free не показує в меню Python-скрипти, а Lua-скрипти з меню працюють у «пісочниці»: немає `io`, `os.execute`, `ffi`, `require`, сокетів, а `UIManager` відкриває вікно «доступно в Studio». Тому скрипт у меню — це Lua-міст, який сам програму запустити не може. Як і в AutoSubs (функція «Open from Resolve»), програма стартує прихованою разом з Windows (`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`) і відкриває вікно, щойно скрипт у Resolve подає сигнал. Закриття вікна зупиняє всю роботу; програма знову чекає прихованою, не тримаючи моделей у пам'яті.

Поки панель закрита, скрипт у Resolve не робить жодного виклику Resolve API, лише раз на пів секунди перевіряє дві теки. Кожен виклик API проходить через чергу інтерфейсу Resolve, а частий цикл викликів змушував курсор блимати. Коли панель відкрита, скрипт оновлює плейхед 2,5 рази на секунду, а таймлайн перевіряє раз на секунду.

Програма під час старту сама оновлює свій скрипт у теці Resolve. Якщо перезапустили Resolve, запустіть пункт меню ще раз. Журнал: `data\app.log` у теці програми.

## Робота

1. **Транскрибувати**. Розпізнається мова в кліпах вибраної доріжки (за замовчуванням V1, перемикач угорі). Розпізнавання робить модель **Parakeet TDT 0.6B v3 UK** ([ihnatov-yuri/parakeet-tdt-0.6b-v3-uk](https://huggingface.co/ihnatov-yuri/parakeet-tdt-0.6b-v3-uk)), донавчена на українську. Англійські слова й назви вона пише латиницею, вибирати мову не треба. Модель працює на відеокарті NVIDIA (CUDA-збірка torch), а без неї — на процесорі. Якщо відеопам'яті не вистачає (наприклад, її займає Resolve), розпізнавання автоматично продовжується на процесорі. Довгі записи ріжуться на фрагменти до 20 с у паузах. Довге мовлення без пауз ріжеться в найтихшому місці, з перекриттям, тож слова на межах не губляться й не повторюються. Визначення мовців працює через pyannote і потребує токена Hugging Face:
   - на https://hf.co/pyannote/speaker-diarization-community-1 прийміть умови (Agree);
   - на https://hf.co/settings/tokens створіть токен типу **Read**. Якщо токен **fine-grained**, увімкніть у ньому «Read access to contents of all public gated repos you can access» — без цього Hugging Face відповідає 403, хоча сам токен дійсний.

   Доступ перевіряється **до** розпізнавання, з поясненням, що виправити. Мовців для вже готової транскрипції можна визначити окремо: «Транскрибувати» → «Лише визначити мовців». Без pyannote мовців призначають вручну: ПКМ на імені мовця. Перейменування — там само або на вкладці «Мовці».
2. **Монтаж текстом**:

| Дія | Як |
|---|---|
| Виділити | протягнути мишею по словах, `Shift`+клік, `Shift`+стрілки; подвійний клік — речення, потрійний — абзац. Над виділенням з'являється панель дій. Кнопка `?` над текстом — коротка довідка |
| Подивитися шматок | «Програти» на панелі дій: Resolve ставить In/Out на виділення, виходить на передній план і програє рівно цей шматок |
| Вирізати слова / речення / фрагмент | виділити → `Del` |
| Повернути вирізане | клік по «вирізано · N слів» → виділити закреслені слова → `Del` |
| Перенести | затиснути на виділеному й тягнути: блимаючий курсор «сюди» показує місце (ліва половина слова — перед ним, права — після); відпустити. `Esc` — скасувати |
| Копіювати | те саме перетягування з затиснутим `Ctrl`; або `Ctrl+C` → `Ctrl+V` перед виділеним словом (`Ctrl+X` — вирізати в буфер) |
| Виправити мовця | виділити слова → ім'я потрібного мовця на панелі дій (або `1`–`9` — номер у легенді); «+» — новий мовець |
| Дублювати | `Ctrl+D` |
| Скасувати / повторити | `Ctrl+Z` / `Ctrl+Shift+Z` |
| Перейти на таймлайні | клік по слову, таймкоду кліпа або id фрагмента |
| Виправити текст | подвійний клік по слову (на відео не впливає) |
| Пошук | `Ctrl+F`, `Enter` / `Shift+Enter`; знайдене виділяється — можна одразу `Del` |

Слова пофарбовано в колір мовця (легенда над текстом; клік по імені — перейменувати); зміна мовця не розриває текст. Паузи від 3 с показано окремими позначками, новий абзац — після паузи від 6 с або коли абзац задовгий. Після визначення мовців дрібні «перескоки» (1–3 слова посеред чужої фрази) прибираються, а межа між мовцями зсувається на кінець речення. Теми від мовної моделі показано заголовками з одним реченням опису. Ліворуч — структура відео за кліпами й мовцями.

Слово під плейхедом Resolve підсвічується червоним (кнопка-прапорець вмикає автопрокрутку).

3. **Експорт для Claude** (будь-яка мовна модель): у вікні задаєте **тривалість** (Shorts, коротке, середнє, довге або своя), **кількість варіантів** і своїми словами **що потрібно**; це зберігається в проєкті. Програма складає текстовий запит (`*.prompt.txt`): завдання, правила, коротку схему відповіді й матеріал рядками `B12-B15 [12:03 · 18 с] Олексій: … Марко: …` (id фрагментів, початок у файлі, тривалість, текст; рядок — шматок мовлення до довгої паузи). «Копіювати запит» кладе його в буфер для вставки в чат. Після імпорту варіант, набагато коротший чи довший за замовлене, позначається попередженням.
   - До ≈35 тис. токенів (кілька годин розмови) — один запит.
   - Довший запис ділиться на частини. **Етап 1:** кожну частину дайте моделі, вона виділить ключові моменти (`davinci-director.beats/1`), відповідь кожної частини імпортуйте. **Етап 2:** «Етап 2» дає запит з усіма моментами, з якого модель складає відео за вашим завданням.
   - **Теми:** окремий короткий запит «Копіювати запит на теми» — модель ділить розмову на теми (`davinci-director.topics/1`), і після імпорту вони стають заголовками в тексті. «Прибрати теми» — там само.
4. **Імпорт сюжетів**: файл або вставлений текст відповіді (markdown-обгортка допускається). Застосунок сам розпізнає сюжети, теми чи моменти етапу 1. Варіанти з'являються на вкладці «Сюжети».
5. **Структура сюжету**: сцени з назвою, описом, роллю, фрагментами (клік — перехід у Resolve; закреслені — зараз не на таймлайні), діапазоном у джерелі, тривалістю, порадами з монтажу, переходом, контекстом і закадровим текстом (редагується). Сцени можна перетягувати й вимикати.
6. **Застосування**:
   - «Застосувати: новий таймлайн» — створює в проєкті новий таймлайн `<назва> — <варіант>` з кліпами в порядку сцен, маркерами сцен (колір за роллю) і жовтими маркерами з текстом VO. Початковий таймлайн не змінюється. Скасування повертає попередній таймлайн.
   - «Замінити монтаж» — перебудовує доріжку поточного таймлайна.
   - Окрема сцена: «У плейхед» (на найближчу межу кліпа) або «У кінець».
7. Далі монтуйте в Resolve як завжди: текст стежить за змінами.

## Архітектура

```
DaVinci Resolve (Free або Studio)                       DaVinci Director
┌──────────────────────────────────────┐   файли     ┌──────────────────────────────────┐
│ Workspace > Scripts > DaVinci Director│◀─────────▶│ link.py     міст                  │
│  DaVinci Director.lua (фоновий цикл)  │ %TEMP%\     │ engine.py   синхронізація         │
│   • команди: імена тек  bridge\in     │ DaVinci-    │ stories.py  експорт/імпорт/сюжети │
│   • відповіді: імена файлів bridge\out│ Director\   │ transcribe.py Parakeet + pyannote │
│   • стан: Timeline.Export(OTIO)       │ bridge      │ server.py + web/  інтерфейс       │
│   • стежить за змінами таймлайна      │             └──────────────────────────────────┘
└──────────────────────────────────────┘
```

**Чому файли.** У «пісочниці» Lua в Resolve 21 Free лише кілька способів обмінюватися даними. Усе нижче перевірено наживо на Resolve 21.2 Free:

- `MediaStorage:GetSubFolderList(path)` читає імена тек. Застосунок записує команду (hex) в імена тек у `bridge\in`, великі команди діляться на частини.
- `MediaPool:ExportMetadata(path, {clip})` записує крихітний CSV під довільним ім'ям (~2 мс). Скрипт відповідає файлами, ім'я яких містить дані. Resolve сам ставить розширення `.csv`. Запасний варіант — `Timeline:Export(…, EXPORT_EDL)`.
- `Timeline:Export(path, resolve.EXPORT_OTIO)` вивантажує повний стан таймлайна в `bridge\state` (~2 мс): доріжки, кліпи, вихідні діапазони, шляхи до медіа. Час джерела в OTIO Resolve пише в частоті таймлайна, тому FPS кожного медіа міст бере з властивостей кліпа в медіапулі.
- Скриптам дозволено писати лише в деякі теки. `%APPDATA%` і `%LOCALAPPDATA%\DaVinciDirector` заборонені, `%TEMP%` і `Documents` дозволені. Тому тека обміну — `%TEMP%\DaVinciDirector\bridge`.
- Що не працює: `bmd.copyfile` (сам реалізований через `io`, тому падає); `fusion:SetData` записує `Fusion.prefs` лише після завершення скрипта; `io`, `ffi`, `require`, `os.execute` відсутні; Python-скрипти не показуються в меню; `fusion:RunScript` і `fusion:Execute("!Py3: …")` не виконують сторонній код; `UIManager` показує вікно «доступно в Studio». External scripting доступний лише в Studio.

**Синхронізація (головне).** Єдине джерело правди — таймлайн Resolve.

- Транскрипція належить **вихідному медіафайлу**: кожне слово має час у секундах від початку файлу. Фрагменти (репліки) отримують незмінні id `A0001…` (буква — медіафайл, число — номер фрагмента). Вони не залежать від таймлайна, тому сюжети й експорт для Claude лишаються дійсними після будь-яких правок.
- Текст **виводиться** з поточного таймлайна. Для кожного кліпа доріжки в порядку таймлайна показуються слова, що потрапляють у його вихідний діапазон (`source in/out`). Тому видалення, перестановка, обрізання чи новий кліп у Resolve автоматично змінюють текст. Слова, яких немає в жодному кліпі, показуються як вирізані поруч зі своїм сусідом у джерелі.
- Lua-скрипт кожні ~0,25 с порівнює «відбиток» таймлайна (межі й зміщення всіх кліпів). Після зміни він вивантажує стан, застосунок перебудовує текст. Плейхед передається окремо.
- Правка тексту перетворюється на операції над реальними кліпами й виконується у фазах. Після кожної фази застосунок перечитує фактичний стан таймлайна:
  1. розрізання: обрізати кінець кліпа й додати залишок з того самого медіа на те саме місце;
  2. ripple-видалення, ripple-вставка або переміщення блоку (через «паркування» за кінцем таймлайна) від фактичних меж кліпів;
  3. закриття розривів у 1–3 кадри, які Resolve може залишити через округлення, коли fps медіа й таймлайна різні (наприклад, стрім 60 fps на таймлайні 24 fps).

  Після кожної правки текст будується з нового стану. Текст і таймлайн не можуть розійтися: текст — це функція таймлайна. Наживо одна правка займає 0,25–0,8 с.
- Undo/Redo застосунку виконує обернені операції. Якщо таймлайн змінили в Resolve, історію буде скинуто — тоді використовуйте Ctrl+Z у Resolve.

**Використані функції API** (з `Developer/Scripting/DaVinciResolveScript.pyi` версії 21.2): `GetItemListInTrack`, `GetStart/GetEnd`, `Get/SetLeftOffset`, `Get/SetRightOffset` (21.1.2+), `GetLinkedItems`, `GetMediaPoolItem`, `MediaPool.AppendToTimeline([{mediaPoolItem, startFrame, endFrame, recordFrame, trackIndex, mediaType}])`, `Timeline.DeleteClips`, `Timeline.MoveItems` (21.1.2+), `Get/SetCurrentTimecode`, `CreateEmptyTimeline`, `SetCurrentTimeline`, `AddMarker`, `Timeline.Export(EXPORT_OTIO)`.

Поведінку API виміряно на Resolve 21.2: зміщення рахуються в кадрах таймлайна; `endFrame` в `AppendToTimeline` — у кадрах джерела, виключно; `DeleteClips` не видаляє пов'язане аудіо (міст додає його сам); `MoveItems` зсуває групу, навіть якщо вона перекриває своє ж старе місце.

## Обмеження

- Resolve не надсилає подій про зміни таймлайна, тому зміни відстежуються опитуванням усередині Resolve (~0,25–0,5 с, інтервал адаптується до розміру таймлайна).
- Розрізання робиться обрізкою кліпа з додаванням залишку тим самим медіа. Ефекти, грейд, переходи й швидкість з першої половини кліпа на залишок **не копіюються**. Монтуйте текстом до кольорокорекції та ефектів.
- Ripple зсуває кліпи редагованої доріжки та пов'язане з ними аудіо. Незв'язані кліпи інших доріжок (музика, B-roll) не рухаються.
- Підтримується швидкість кліпів 100%. Різні fps медіа й таймлайна підтримуються, але межі округлюються до кадру таймлайна. Кожне розрізання може «з'їсти» до 1 кадру (на тесті 60→24 fps: 6 кадрів за ~10 правок).
- «Прибрати розриви на доріжці» (меню «…») закриває всі розриви між кліпами доріжки. Знадобиться після ручних видалень у Resolve без ripple.
- Lua-скрипт потрібно запускати з меню після кожного старту Resolve: Resolve не дозволяє автозапуск скриптів, а скрипт у Free не може запустити застосунок сам.
- `Timeline:Export` для великого таймлайна займає частку секунди й виконується лише після змін. Якщо експорт не вдасться, міст передасть компактний стан доріжки.
- API Resolve не має команди «Програти», а під час відтворення не повідомляє скриптам позицію плейхеда. Тому «Програти» виводить вікно Resolve наперед, натискає Space і через тривалість шматка натискає Space ще раз (на тесті зупинка точно в кадр Out). Якщо за цей час перемкнутися з Resolve в інше вікно, зупинки не буде — зупиніть пробілом у Resolve.
- Маркери сцен і VO ставляться за `AddMarker` у кадрах від початку таймлайна.
- Визначення мовців потребує pyannote і токена Hugging Face з доступом до gated-моделей. Без них мовців призначають вручну. На CPU-збірці torch визначення мовців для години запису займає кілька хвилин.

## Збірка інсталятора для друзів

```powershell
.venv\Scripts\python build.py
```

Результат: `dist\DaVinciDirector-Setup-<версія>.exe` (близько 15 МБ). У ньому лише офіційний вбудований Python з python.org, pip, pywebview (власне вікно програми на WebView2, вбудованому у Windows: без панелей і розширень браузера), код програми і шрифт Open Sans (SIL Open Font License, `web/fonts/OFL.txt`) — жодних важких бібліотек.

**Усе в одній теці.** Інсталятор питає, куди ставити програму; за замовчуванням пропонує користувацьку теку DaVinci Resolve `%APPDATA%\Blackmagic Design\DaVinci Resolve\Support\DaVinci Director`, але можна обрати будь-яку теку, у яку можна писати без прав адміністратора (наприклад, на іншому диску — знадобиться кілька ГБ). Програмі потрібна власна тека: корінь диска чи теку з іншими файлами інсталятор замінить на підтеку `DaVinci Director`. Оновлення ставиться в ту саму теку. У обраній теці лежить усе, що програма завантажує й зберігає: компоненти (`components`), моделі (`models`, `hf`), транскрипції, сюжети, налаштування, журнали й кеші бібліотек (`data`). Кеші Hugging Face, pip, matplotlib і torch спрямовано туди ж, тож у профілі користувача нічого не з'являється. Поза цією текою лише тека обміну зі скриптом Resolve в `%TEMP%\DaVinciDirector` (пісочниця скриптів Resolve пише лише туди) і запис автозапуску прихованого процесу в реєстрі. Видаляється програма через «Параметри → Програми»: разом зі скриптом у Resolve, компонентами й моделями; про транскрипції й налаштування деінсталятор питає окремо.

Програма сама завантажує те, що потрібно, коли воно вперше знадобиться:

| Компонент | Коли | Розмір |
|---|---|---|
| Аудіо й пошук мовлення: PyAV (бібліотеки FFmpeg), Silero VAD (onnxruntime) | перша транскрипція | ≈ 60 МБ |
| Нейромережі: torch + transformers (Parakeet) + pyannote (мовці). З відеокартою NVIDIA (драйвер з CUDA 13) ставиться CUDA-збірка torch | перша транскрипція | ≈ 3 ГБ з CUDA, ≈ 1 ГБ без |
| Модель Parakeet TDT 0.6B v3 UK | перша транскрипція | 2,5 ГБ |

Завантаження багатопотокове: файли качаються паралельно, а великі (модель, torch) ще й частинами в кілька з'єднань. Перерване завантаження продовжується з місця зупинки, обриви мережі повторюються автоматично, цілісність перевіряється за SHA-256 з PyPI і Hugging Face, місце на диску перевіряється заздалегідь. Прогрес (МБ, швидкість, скільки лишилось) видно в рядку стану. У меню «…» → «Компоненти й моделі» можна завантажити компоненти заздалегідь або видалити їх.

Під час збірки `build.py` один раз завантажує в `build\cache` вбудований Python (`python-<версія>-embed-amd64.zip` з python.org, ~11 МБ). Якщо Inno Setup 6 не встановлено, він також завантажує його інсталятор (`is.exe` з jrsoftware.org, ~6 МБ) і ставить його для поточного користувача в `build\tools`. Після збірки — самоперевірка вбудованого Python і коду.

## Розробка

`python install.py` створює `.venv` і запускає програму прихованою, як в інсталяторі. Перевірка — у справжньому DaVinci Resolve. Після зміни коду перезапустіть програму: `python install.py --uninstall`, потім `python install.py`.
