# DaVinci Director

AI-аддон для DaVinci Resolve. Допомагає перетворити довгий запис ігрового стріму на структуроване відео для YouTube: транскрибування з таймкодами слів і мовцями, текстовий монтаж, пошук сюжетів через Claude, редактор структури відео й перенесення результату на таймлайн Resolve.

```
Workspace ▸ Scripts ▸ DaVinci Director
┌──────────────┬───────────────────────────────┬────────────────────┐
│ В'ювер        │ Транскрипція = монтаж          │ Сюжети │ Claude │…  │
│ (порядок      │ виділіть → Del, перетягніть,   │ варіанти, сцени,   │
│  монтажу)     │ Ctrl+C/V, дублювання, пошук    │ hook, VO, прийоми  │
│ Мовці/Пошук   │                                │                    │
├──────────────┴───────────────────────────────┴────────────────────┤
│ огляд запису: що залишено / вирізано / сцени сюжету / гучні моменти │
└────────────────────────────────────────────────────────────────────┘
```

## Можливості

| Блок | Що вміє |
|---|---|
| **Транскрибування** | FFmpeg витягує аудіо використаних фрагментів таймлайну, [faster-whisper](https://github.com/SYSTRAN/faster-whisper) розпізнає мову з таймкодом кожного слова (`large-v3`, `large-v3-turbo`, …). Мовців визначає pyannote.audio (опційно). Також можна імпортувати SRT/VTT (наприклад, субтитри з Resolve «Create Subtitles from Audio») або JSON Whisper/WhisperX. Мовців можна перейменувати й перепризначити, слова виправити (подвійний клік). |
| **Текстовий монтаж** | Видалення слів, речень і фрагментів (Del), відновлення (Del по вирізаному або «Відновити»), перестановка фрагментів (перетягування, Alt+↑/↓), копіювання/вставка (Ctrl+C / Ctrl+X / Ctrl+V), дублювання (Ctrl+D), розділення (S) й об'єднання, пошук по всьому запису (Ctrl+F) з масовим вирізанням збігів, скорочення пауз, вирізання слів-паразитів, повний undo/redo. Клік по слову переміщує плейхед у в'ювері й у Resolve. |
| **Паузи як текст** | Відрізки без мови (чистий геймплей) стають токенами `··· 4.2s`, тож їх теж можна вирізати, переставляти чи залишати. Сплески гучності (крики, вибухи) позначено ⚡. |
| **Синхронізація з Resolve** | «▸ На таймлайн Resolve» (або автосинхронізація) будує окремий таймлайн `<назва> — DD Edit` з оригінального медіа, кадр у кадр, з маркерами сцен і закадрового тексту. Оригінальний таймлайн не змінюється. Плейхед Resolve підсвічується в тексті (і в оригіналі, і в монтажі). |
| **Claude: пошук сюжетів** | Кнопка «✦ Знайти сюжети з Claude» надсилає транскрипцію (з паузами й ⚡) і отримує кілька концепцій відео: огляд, сильні моменти з оцінкою, варіанти hook, послідовність сцен із ролями, діапазонами оригіналу, коментарями до монтажу, прийомами й закадровим текстом, а також слабкі місця, брак контексту й ідею завершення. Лише реальні події, кожна рекомендація з таймкодами. |
| **Редактор структури** | Сцени можна переставляти (drag & drop), вимикати, видаляти, перейменовувати, міняти роль, редагувати описи, діапазони (Alt+клік), VO; додавати сцени й діапазони з виділеного тексту; переглядати сцену чи весь варіант у в'ювері. «Застосувати до монтажу» перебудовує монтаж за сценами. Поки варіант прив'язаний, зміни структури одразу оновлюють монтаж (ваші вирізання всередині сцен зберігаються). |
| **Чат з Claude** | Окрема вкладка в контексті відео: Claude бачить транскрипцію, поточний монтаж і всі варіанти. Може зберегти новий або змінений варіант сюжету інструментом `save_story_variant`. Таймкоди у відповідях клікабельні. |
| **Збереження** | Проєкт (транскрипція, монтаж, сюжети, чат) автоматично зберігається в `~/.davinci_director/projects/` для кожного таймлайну й відкривається після перезапуску. |
| **Експорт** | SRT монтажу чи оригіналу (субтитри для YouTube), TXT, EDL (CMX3600), сценарій варіанта в Markdown. |

## Встановлення

Потрібні DaVinci Resolve 18.5+ (Free або Studio), Python 3.9+ і FFmpeg у `PATH`.

```bash
git clone <repo> DavinciDirector && cd DavinciDirector
python install.py               # .venv + залежності + пункт меню в Resolve
python install.py --diarization # додатково pyannote.audio для визначення мовців
python install.py --webview     # нативне вікно (pywebview) замість браузерного
```

Інсталятор записує лаунчер у теку скриптів користувача:

| ОС | Тека |
|---|---|
| Windows | `%APPDATA%\Blackmagic Design\DaVinci Resolve\Support\Fusion\Scripts\Utility` |
| macOS | `~/Library/Application Support/Blackmagic Design/DaVinci Resolve/Fusion/Scripts/Utility` |
| Linux | `~/.local/share/DaVinciResolve/Fusion/Scripts/Utility` |

Перезапустіть Resolve. Щоб Resolve запускав `.py`-скрипти, у системі має бути Python 3 (Resolve шукає системний інтерпретатор).

**Ключі** (⚙ у панелі або змінні середовища):
- `ANTHROPIC_API_KEY` — для Claude. Модель за замовчуванням: `claude-opus-5-5`. Можна обрати Fable 5.2, Sonnet 5.5 чи Haiku 5.5.
- `HF_TOKEN` — для pyannote. Потрібно прийняти умови моделі `pyannote/speaker-diarization-community-1` (або `-3.1`) на Hugging Face.

## Робочий процес

1. Покладіть запис стріму на таймлайн (один або кілька кліпів) і відкрийте **Workspace ▸ Scripts ▸ DaVinci Director**.
2. **🎙 Транскрибувати** → оберіть модель і мову → «Почати». Для 3-годинного запису на GPU `large-v3` працює приблизно 10–20 хв, на CPU краще `small`/`medium` або `large-v3-turbo`.
3. Монтуйте текстом: виділіть зайве → `Del`; перетягніть фрагмент за `⋮⋮`; `Ctrl+C` → клік у потрібне місце → `Ctrl+V`.
4. **✦ Знайти сюжети з Claude** → за бажанням опишіть, яке відео потрібне → отримайте варіанти у вкладці «Сюжети».
5. Відредагуйте структуру варіанта → **Застосувати до монтажу** → за потреби доопрацюйте текстом.
6. Попросіть Claude в чаті: «знайди кращий початок», «скороти середину», «напиши закадровий текст»…
7. **▸ На таймлайн Resolve**: з'явиться таймлайн `… — DD Edit` з маркерами сцен (колір за роллю) і VO (жовті). Далі звичайний монтаж у Resolve: переходи, графіка, звук.

### Гарячі клавіші редактора

| Клавіші | Дія |
|---|---|
| `Del` / `Backspace` | вирізати виділене (повторно — відновити) |
| `Ctrl+C` / `Ctrl+X` / `Ctrl+V` | копіювати / вирізати в буфер / вставити перед словом під курсором |
| `Ctrl+D` | дублювати виділене або фрагмент |
| `Alt+↑` / `Alt+↓` | перемістити фрагмент |
| `S` | розділити фрагмент на слові під курсором |
| `Ctrl+Z` / `Ctrl+Shift+Z` | скасувати / повторити |
| `Ctrl+F` | пошук |
| `Пробіл` | відтворення в'ювера (у порядку монтажу) |
| `Ctrl+Enter` | перенести на таймлайн Resolve |
| ПКМ | контекстне меню: мовці, мітки, сцени, перехід у Resolve… |

## Архітектура й інтеграція з Resolve

```
Resolve (вбудований Python)                     окремий процес (.venv)
┌───────────────────────────────┐   HTTP+token   ┌─────────────────────────────────┐
│ Scripts/Utility/DaVinci        │◀─────────────▶│ davinci_director (python -m)     │
│ Director.py  → bridge.py       │ 127.0.0.1     │  server.py  API + SSE + UI       │
│   resolve_ops.py (лише stdlib) │               │  model.py   рушій текст. монтажу │
│   ⇢ офіційний Resolve API      │               │  transcribe.py  faster-whisper   │
└───────────────────────────────┘               │  media.py   FFmpeg               │
                                                 │  claude_ai.py  Anthropic SDK     │
                                                 └───────────────┬─────────────────┘
                                                                 │ вікно: pywebview / Chromium --app
```

**Чому так.** Ось що ми з'ясували, досліджуючи можливості інтеграції:

- **Workflow Integration Plugins** (HTML/Electron-панелі всередині Resolve) працюють лише в Studio і лише на Windows/macOS.
- **UIManager** (Fusion UI) у нових версіях обмежений Studio. Крім того, він надто бідний для редактора з десятками тисяч слів.
- **Зовнішній скриптинг** (`DaVinciResolveScript` з терміналу) потребує налаштування `External scripting using: Local`, а в Free-версії доступний не завжди.
- **Скрипти з меню Workspace ▸ Scripts** працюють і у Free, і в Studio, і там завжди доступний об'єкт `resolve`.

Тому лаунчер запускається з меню, піднімає маленький локальний міст (лише stdlib, захищений випадковим токеном, слухає тільки 127.0.0.1) і запускає застосунок в окремому Python-оточенні. Важкі залежності (CTranslate2, torch) не потрапляють у процес Resolve, а всі виклики API виконуються в потоці скрипта Resolve. Якщо в Resolve увімкнено зовнішній скриптинг, застосунок можна запустити й напряму: `python -m davinci_director`.

**Використані функції Resolve API.** Лише документовані в `Developer/Scripting/README.txt`:
- читання таймлайну: `GetCurrentTimeline`, `GetItemListInTrack`, `TimelineItem.GetStart/GetEnd/GetLeftOffset/GetMediaPoolItem`, `MediaPoolItem.GetClipProperty("File Path"/"FPS"/"Start TC")`;
- побудова монтажу: `MediaPool.CreateEmptyTimeline`, `AppendToTimeline([{mediaPoolItem, startFrame, endFrame}])`, `Timeline.AddMarker`, `MediaPool.DeleteTimelines`, `Timeline.SetName`;
- навігація: `Timeline.SetCurrentTimecode`, `GetCurrentTimecode`, `Project.SetCurrentTimeline`, `Resolve.OpenPage`.

**Модель монтажу.** Токени (слова й паузи) без проміжків покривають використаний діапазон кожного кліпу. Тому повна транскрипція відтворює оригінал кадр у кадр, а вирізання токена прибирає рівно його медіа-інтервал. Монтаж — це впорядкований список фрагментів (діапазон токенів + множина вирізаних). Рендер склеює суміжні шматки в мінімальну кількість кліпів.

## Обмеження та практичні рішення

- **Resolve API не вміє редагувати кліпи всередині таймлайну по одному** (обрізати чи переставляти). Тому кожна синхронізація перебудовує окремий таймлайн `— DD Edit` повністю. Для 3-годинного запису з сотнями склейок це займає секунди. Оригінальний таймлайн ніколи не змінюється. Робіть фінальний монтаж (графіка, музика) після того, як структура усталиться, або на копії `DD Edit`: наступна синхронізація замінить цей таймлайн.
- **`AppendToTimeline` і `endFrame`.** У різних версіях Resolve `endFrame` трактується по-різному (включно чи ні). Аддон після першої синхронізації вимірює фактичну тривалість кліпу й автоматично калібрується.
- **Вбудована транскрипція Resolve** (Studio) не має API для читання слів із таймкодами. Тому використовується Whisper, а субтитри Resolve можна імпортувати через SRT.
- **В'ювер у панелі** відтворює вихідний файл браузером. Для кодеків, які браузер не підтримує (ProRes, DNxHR, HEVC 10-bit), одним кліком створюється H.264-проксі (FFmpeg). На таймлайн Resolve завжди йде оригінальне медіа.
- **Паузи** нарізано шматками до 6 с, щоб їх можна було частково скоротити. Точніше ріжте вже в Resolve.
- **Різні fps** медіа й таймлайну підтримуються (кадри перераховуються), але найточніший результат — коли fps збігаються.
- **Діаризація** (pyannote) необов'язкова. Без неї всі слова належать «Мовцю 1», і мовців можна призначити вручну (ПКМ ▸ Призначити мовця).
- **Claude** спирається тільки на транскрипцію та аудіо-ознаки. Що відбувається на екрані під час мовчання, він не бачить і позначає такі місця як припущення. Таймкоди з відповіді перевіряються й обрізаються до реального запису, а порожні діапазони відкидаються з попередженням.
- **Довгі записи.** Транскрипція 4–6-годинного стріму (~60–90 тис. токенів) вміщується в контекст (1M). Вона кешується (prompt caching, 1 год), тож повторні запити в чаті дешевші й швидші.

## Розробка й тести

```bash
pip install -r requirements.txt pytest
python -m pytest -q                       # модель монтажу + повний сценарій через міст із mock-Resolve
python tools/demo_server.py video.mp4     # UI без Resolve/Whisper/ключа (синтетичні дані)
python -m davinci_director --mock video.mp4   # реальний Whisper/Claude, mock-таймлайн замість Resolve
```

Тести проганяють повний сценарій: підключення до таймлайну через міст → транскрибування (справжнє витягування аудіо FFmpeg і аналіз гучності) → текстові правки, undo → побудова таймлайну з калібруванням `endFrame` → перехід за словом в оригіналі й монтажі → аналіз Claude (структурований JSON) → застосування й редагування структури → маркери → чат із викликом інструмента → експорти → перезавантаження проєкту.
